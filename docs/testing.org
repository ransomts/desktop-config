#+title: Testing

The shell and scripts have about thirty test suites, all in =home/.local/bin/= as =*-test=. =desktop-test= runs them all in parallel and prints one line per suite, then the failures.

#+begin_src sh
desktop-test            # everything, 10 suites at a time
desktop-test -l         # list the suites
desktop-test clock hypr # only these
#+end_src

Logs go to =~/.local/state/desktop-test/latest/=.

* How they stay out of the way

Each suite runs in its own temporary =HOME=, runtime directory and D-Bus session, with stub commands in place of anything that would touch the real machine (=notify-send=, =systemctl=, =nmcli=, =wpctl=, ...). The stubs record what they were asked to do, and the tests check that record. The QML suites load the pieces they test offscreen; the full shell only runs in the nested ones below.

* The suites

| Suite | Covers |
|-------+--------|
| =hypr-test= | the Hyprland config itself, in a nested Hyprland: it loads clean, autostart, no key bound twice, special workspaces, docking and undocking with headless monitors |
| =shell-boot-test= | the whole shell in a nested Hyprland: it starts and stays up, no QML errors or binding loops, bars on hot-plugged screens, IPC opens and closes each view, and =fit-check= finds nothing cut off |
| =hypr-scripts-test= | the helpers that drive Hyprland through =hyprctl= |
| =qml-panels-test=, =qml-overlays-test= | the bar's popups, panel pieces, overview and other overlays |
| =launcher-test= | the launcher and its modes |
| =notify-test= | the notification core: popups, grouping, rules |
| =settings-test= | the settings window and its pages |
| =health-test= | =shell-health= and the health pill, popup and singleton |
| =devices-test= | Bluetooth audio, the lights (=gvm=), drives and other hardware glue |
| =displays-test= | Settings > Displays and =display-layout= |
| =agenda-test=, =dayflow-test=, =events-test=, =clock-test= | the calendar band, calendar-aware Do Not Disturb, quick events, clocks and time zones |
| =lecture-test=, =capture-test=, =shot-test= | lecture tools; recording, mic and webcam; the screenshot editor and share picker |

| =menus-test=, =data-test=, =palette-follow-test= | picker menus and glue scripts; the Python data sources; the palette following the theme |

* Nested Hyprland

=hypr-test=, =shell-boot-test= and =desktop-shots= start a second Hyprland as a window inside the running session, on its own sockets and buses, with =HYPRLAND_NO_SD_VARS= set and stubs for =systemctl=, =uwsm= and =dbus-update-activation-environment=; otherwise the nested instance would point the real session's systemd environment at itself. Each one checks afterwards that the live session's environment is unchanged.

* fit-check

=fit-check= opens every popup and view of the running shell in turn and reports any text or control drawn where it gets cut off. =shell-boot-test= runs it on a 1920x1080 headless screen.

* Screenshots

The staged session has stand-ins for everything the shell would otherwise read from the machine:

| What | Stand-in |
|------+----------|
| Battery, power profiles, Wi-Fi, Bluetooth | =desktop-shots-fakes=: python-dbusmock's UPower, power-profiles, NetworkManager and BlueZ templates, on a private bus that only looks like the system bus |
| Music | the same script's made-up MPRIS player, with a generated cover |
| Sound | a private PipeWire and WirePlumber in the temporary runtime directory, with the ALSA, Bluetooth and camera monitors switched off, and virtual speakers, headphones, microphone and one app playing silence |
| Webcam | a generated picture where the bubble expects its frames; the camera reader is a stub, so no camera is opened |
| Calendar, mail, Teams, tabs, clipboard, notes, lights, health | made-up files and small scripts in the temporary home |
| Wi-Fi list, clipboard history | stub =nmcli= and =cliphist= that print made-up lines |

python-dbusmock lives in a virtualenv (=~/.local/share/desktop-shots/venv=), made on first use.

=desktop-shots= takes the pictures in =screenshots/= and writes =docs/keybindings.org=:

1. It copies the config from this repo's =home/= (what is published, not my live files) into a temporary home.
2. It starts a nested Hyprland, adds a 1920x1080 headless screen and switches the nested window's own screen off.
3. It runs the shell there with the same isolation as =shell-boot-test=, plus made-up data: a calendar file with a teaching day, canned weather and mail counts, three notifications sent on the private bus, and two Ghostty windows showing files from this repo.
4. For dark and then light, it photographs the empty desktop, the desktop with windows, and each view (opened through =qs ipc=), with =grim= on the headless screen. Ink and the spotlight's pointer come from =vptr=, a virtual pointer client from the strict-resize plugin's tests; the key display is fed made-up key presses instead of reading keyboards.
5. In dark only: two launcher modes with a query typed, and every wallpaper scene at a quarter size, laid out in a grid.
6. Animations: =wf-recorder= records the nested screen for a few seconds while a script does something (sends a notification, switches the theme, has the island speak), and =ffmpeg= turns the clip into an animated WebP, which GitHub shows like a picture.
7. The screenshot editor, driven by =vptr= and =vkbd= (a virtual keyboard: real key presses, so tool keys work). It comes late because the virtual keyboard's US keymap shows in the bar's layout pill from then on.
8. The lock screen, last, since nothing unlocks it: one lock per mode, killing the first and starting the second (=allow_session_lock_restore=).
9. The gallery (=desktop-shots-gallery=): every bar popup, launcher mode and settings page, the overlays, the pet's pages, the wallpaper effects, and four interaction clips. Each still is cropped to what the view added: a picture from just before it opened is compared with one after. Stills are AVIF at full colour resolution, a sixth the size of a PNG.
10. It dumps the nested session's bindings and runs =keybind-sheet --org= on them, then shrinks the PNGs with =pngquant=.

#+begin_src sh
desktop-shots                      # all shots, both modes
desktop-shots --only launcher,panel --dark-only -o /tmp/shots
desktop-shots --no-anim           # stills only
desktop-shots --hold               # set up the session and wait, for working on the script
#+end_src
