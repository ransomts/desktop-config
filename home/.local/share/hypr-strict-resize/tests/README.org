#+title: Testing strict-resize and the Hyprland keys

Test in a nested Hyprland first, never first in the live session.

- Start one: =PATH=$PWD/nosd:$PATH env -u UWSM_FINALIZE_VARNAMES -u UWSM_WAIT_VARNAMES HYPRLAND_NO_SD_VARS=1 HYPRLAND_NO_SD_NOTIFY=1 Hyprland -c test.lua= from a terminal (it opens as a window). =nosd/= holds do-nothing =systemctl= and =dbus-update-activation-environment= scripts; see the note on the session environment below. A minimal =test.lua= loads the plugin under test with =pcall(hl.plugin.load, PATH)=, =dofile= on the =layouts.lua= under test, sets =dwindle = { preserve_split = true }= like the real config, and opens a few =kitty= windows on =hyprland.start=. Its socket shows up as a new directory in =/run/user/1000/hypr/= (=hyprctl -i SIG ...=) and its Wayland display is the next =wayland-N=.
- =./build.sh= builds the input clients. =vptr W H cmds= (W H = the nested monitor's logical size): =m X Y= move, =d=/=u= left button, =D=/=U= right button, =w N= wheel notches, =s MS= sleep. =vkbd cmds=: =d CODE= / =u CODE= press / release an evdev key code, =t CODE= tap, =s MS= sleep (125 Super, 29 Ctrl, 42 Shift, 56 Alt, arrows 105 106 103 108). wtype only fakes modifier state, so Hyprland key bindings never fire from it.
- =kbtest.py= checks Super+Ctrl+arrows on every window of a layout (=--layouts 'Layouts.set(1, "dwindle")' ...=); =keytest.py= checks Super+H/K/Y/Shift+Y/Shift+M/J. Both read =nested.sig= and =nested.wl= (the instance's signature and Wayland display) from this folder.
- vkbd uploads a US keymap, so the bar's keyboard pill reads "US" after using it on the live session until the next real keystroke; the real keyboards keep Dvorak.
- The nested instance sometimes ignores =exit=; =kill -9= its pid.
- A nested instance rewrites the session's systemd environment (=WAYLAND_DISPLAY=, =DISPLAY=, =HYPRLAND_INSTANCE_SIGNATURE=, and =PATH= from the shell that started it) to point at itself: 0.57's exec-once start (=src/config/supplementary/executor/Executor.cpp=) runs =systemctl --user import-environment ...= and =dbus-update-activation-environment= without checking =HYPRLAND_NO_SD_VARS= (that flag only covers =Compositor.cpp=). Stripping the =UWSM_*= variables did not stop it (2026-11-17); the =nosd/= stubs on =PATH= do. Check =systemctl --user show-environment= afterwards anyway; fix with =systemctl --user set-environment= and =dbus-update-activation-environment --systemd= using the live values (=PATH= from =/proc/<live Hyprland pid>/environ=).
- Drag-to-place (v1.4): bind =SUPER + mouse:272= to =hl.dsp.window.drag()= in the test config, hold Super with =vkbd d 125 s 2500 u 125 &= and drag with =vptr W H m X1 Y1 s 100 d s 100 m X2 Y2 s 1500 u=; =grim= during the final sleep shows the preview (after the button is released the drop has already happened). =hyprctl output create headless NAME= adds a second monitor for the cross-monitor case; the vptr extent then becomes the bounding box of both.
- Drag-to-place v1.5 checks: =fuzz.py= style runs (random Super+drags, half aimed at gaps, comparing the logged preview box with where the window ends up) need a temporary debug log in =decideDrop=; the shipped build has none. Esc: =vkbd t 1= while the button is held.
